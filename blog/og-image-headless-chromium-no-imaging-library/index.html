Making an Open Graph image with headless Chromium and no imaging library

26 October 2026 · 2 min read

My site's og-image.png returned a 404, so every link shared to LinkedIn or WhatsApp had no preview card. I needed a 1200×630 PNG, on a server that has Chromium (from Playwright's cache) but no Pillow or ImageMagick.

The plan: write the card as a small HTML file and screenshot it.

chrome --headless --no-sandbox --hide-scrollbars \
  --window-size=1200,630 --screenshot=og-image.png file:///tmp/og.html

The white band

The PNG came out 1200×630, but the bottom 87 pixels were white. In the old headless mode the window size includes browser chrome, so the page's viewport was only 543 pixels tall and the rest of the screenshot was blank canvas. I tried --headless=new on this build and got the same band.

The fix was to ask for a taller window (630 + 87 = 717), then cut the PNG back to 630 rows.

Cropping a PNG with zlib

You do not need an imaging library to trim the bottom off a PNG. Each row is filtered against the row above it, never the row below, so the first N rows are still a valid image. Decompress the IDAT data, keep N * (1 + width * bytes_per_pixel) bytes, recompress, change the height in IHDR and recompute the CRCs:

import zlib, struct
d = open("full.png", "rb").read()
pos, chunks = 8, []
while pos < len(d):
    n = struct.unpack(">I", d[pos:pos+4])[0]
    chunks.append((d[pos+4:pos+8], d[pos+8:pos+8+n])); pos += 12 + n
ihdr = next(c for t, c in chunks if t == b"IHDR")
w, h, bit_depth, color_type = struct.unpack(">IIBB", ihdr[:10])
bpp = {2: 3, 6: 4}[color_type] * bit_depth // 8
raw = zlib.decompress(b"".join(c for t, c in chunks if t == b"IDAT"))
H = 630
stride = 1 + w * bpp
def chunk(t, c):
    return struct.pack(">I", len(c)) + t + c + struct.pack(">I", zlib.crc32(t + c))
out = (d[:8]
       + chunk(b"IHDR", struct.pack(">IIBBBBB", w, H, bit_depth, color_type, 0, 0, 0))
       + chunk(b"IDAT", zlib.compress(raw[:stride * H], 9))
       + chunk(b"IEND", b""))
open("og-image.png", "wb").write(out)

This only handles 8-bit RGB and RGBA, which is what Chromium produces. It would not work on interlaced PNGs.

A favicon.ico, same trick

An ICO file can embed a PNG as-is. The file is a 6-byte header, one 16-byte directory entry, then the PNG bytes:

png = open("48.png", "rb").read()
hdr = struct.pack("<HHH", 0, 1, 1) + struct.pack("<BBBBHHII", 48, 48, 0, 0, 1, 32, len(png), 22)
open("favicon.ico", "wb").write(hdr + png)
